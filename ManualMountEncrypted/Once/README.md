# 一次性挂载

在自己的电脑上生成一对文件：`once-<编号>.sh` 和 `once-key-<编号>`。同事电脑上只输入临时口令。对了，脚本才把卷口令交给现有的 VeraCrypt 挂载，然后粉碎这一对文件。

卷口令不改，单独也能开盘。密钥文件丢了，用卷口令照样能开。这不是 VeraCrypt 的 keyfile。

本目录是生成器。同事电脑上的脚本不需要 python。生成这台电脑需要 python3 和 gcc。同事电脑要是 64 位 Linux，并且有 bash、base64、veracrypt。curl 或 wget 用来对时，没有也能跑，只是对不上网络时间。

## 生成

在要放下文件的目录里执行。不写目录，就生成在当时的当前目录。

```bash
/路径/ManualMountEncrypted/Once/mk-once.sh
/路径/ManualMountEncrypted/Once/mk-once.sh -2
/路径/ManualMountEncrypted/Once/mk-once.sh --days 1
/路径/ManualMountEncrypted/Once/mk-once.sh --digits 20
```

- 直接运行：按 `config.sh` 默认生成一组临时口令，只显示一次。
- `-2`：生成两组。每组各有一个临时口令、一个脚本、一个密钥文件。卷口令只问一遍，打印出来核对，各组共用。数字从 1 到 99。生成完只列出到期时间、临时口令、脚本和密钥文件；口令黄色，脚本青色，密钥文件绿色。
- `--days 7`：覆盖 `expireDays`。不写用配置，默认 15 天。
- `--digits 20`：覆盖 `pinDigits`。最少 16 位。
- `--manual`：自己输入临时口令，不自动生成。

临时口令和卷口令只从终端读，不进命令参数，也不进 shell 历史。临时口令不能和卷口令相同。

把 `once-key-*` 剪到 U 盘上。脚本留在能按下面的 `veraRel` 找到 `VeraCrypt` 的位置。密钥文件也可以放在脚本自己所在的目录，或这个目录下两层以内的文件夹里，文件名必须仍是 `once-key-<编号>`。

## 配置

写在本目录的 `config.sh`。改完要重新生成。已经生成的 `once-*.sh` 里是旧配置。

生成默认：`expireDays`（默认 15）、`pinDigits`（默认 16）、`pinNumeric`（1=纯数字 PIN，0=字母数字）。命令行 `--days` / `--digits` 可覆盖前两项。

`veraRel` 是相对 **生成出的脚本** 所在目录，不是相对本文件。当前是 `./VeraCrypt`：脚本放在 `ManualMountEncrypted` 里，旁边就是 `VeraCrypt` 目录。脚本如果放在本目录，应写成 `../VeraCrypt`。脚本如果直接放进 `VeraCrypt` 目录，写成 `.`。

找不到这个相对路径时，脚本再看自己旁边有没有 `lib.sh` 和 `config.sh`。不写死生成机上的绝对路径。

`timeUrl` 一行一家。对时不是 NTP，读的是这些网站 HTTPS 响应里的日期。慢的删掉，或在前面加 `#`。至少留两家。`timeTimeout` 是每一家最多等几秒，`timeWait` 是全部最多等几秒。已经有两家对上就提前结束。

脚本总会读本机时间。网络已过期一定会粉碎。`localExpireDestroy=1`（默认）时，本机时钟已过期也会粉碎。`localExpirePriority=1`（默认）时，本机已过期会立刻粉碎，不等网络对时；改成 `0` 则先对网络再决定。两个都改成 `0` 时，本机过期只停止不删（防本机被拨快误删）。

## 在同事电脑上

先在文件管理器里打开 U 盘，再运行 `once-*.sh`。不要在命令后面加别的参数。只要进度可以加 `-v`，会打出 `· 1/8` 到 `· 8/8`，不写具体在做什么。

查找顺序：

1. 脚本自己所在的目录，以及往下最多两层。
2. 已经挂上的可移动盘，同样最多两层。
3. 都没有，才让你输入一个目录。

必须恰好找到一个同名密钥文件。零个或两个都停，不删除。不会去扫 `/`、`/home`、`/root` 整棵树。

然后检查脚本和密钥文件能不能写、是不是普通文件、是不是符号链接、有没有第二个硬链接，以及有没有调试器或别的进程在读这个进程的内存。这些不过，不询问口令，也不删除。

再对时间：先读本机时钟。若本机已过期且 `localExpireDestroy=1`、`localExpirePriority=1`（默认），立刻粉碎，不再对网络。否则再试网络；至少两家日期彼此差不超过 48 小时才采用。网络已过期粉碎。本机已过期但优先级关掉时，对完网络后再按 `localExpireDestroy` 决定删或不删。把本机拨慢仍可能躲开本机这一关；网络过期仍会删。

临时口令对了就挂载。卷已经挂着，不询问，也不删除。挂载成功后只粉碎刚才对上的那一个密钥文件和这个脚本。粉碎前再核对文件名、内容和 inode。对不上就两个都不删。口令错或挂载失败，也不删除。

## 卷口令怎么包着

脚本里没有卷口令。密钥文件格式是 `ONCEKEY2`：

- 16 字节随机盐
- scrypt 参数：N=65536，r=8，p=1，大约 64MB 内存
- 卷口令补齐后和 scrypt 密钥流异或得到的密文
- 覆盖盐、密文和到期时间的 HMAC-SHA256（改 `expires` 字段会让正确 PIN 也对不上）

解密先对 HMAC。临时口令不对，就不做异或，也不会吐出卷口令。错一次没有锁定，因为校验可以离线做。

helper 判定过期用 `max(本机时间, 脚本传入的时间)`，不能靠传入一个很小的 `now` 绕过。把本机拨慢仍可能躲开这一关。旧的 `ONCEKEY1` 密钥文件不能用。

## 经不经得起暴力破解

扛得住的是 **自动生成的 16 位随机数字 PIN**。

这台电脑上，按上面的 scrypt 试一次大约 0.12 秒，并且要大约 64MB 内存和大量随机读写。16 位数字有 10^16 种。单核按这个速度要三千多万年。攻击方就算快一个数量级、再堆很多台机器，仍然不实用。这种 scrypt 也不能像猜 SHA256 那样在显卡上开海量并行。

这保护的是「只有密钥文件、没有 PIN」的情况。PIN 一旦和密钥文件凑在一起，不需要暴力破解，卷口令就能被还原。

下面这些情况，这层包装帮不上，卷口令要自己够长、够随机：

- 别人复制了加密分区或卷头。他攻的是 VeraCrypt 自己的口令变换，根本不走这个 scrypt。卷口令又短又常见，密钥文件保护得再好也能被直接猜。
- 同事电脑上临时口令输入之后，卷口令会在内存里交给 veracrypt。当时能读那台机器内存的人，拿到的是卷口令明文。
- 键盘记录看到的是临时 PIN。他如果事先拷走了密钥文件，PIN 加上这份拷贝就能还原卷口令。脚本只会粉碎它这次打开的那一个文件，不会去找别的拷贝。
- `--manual` 自己设的短口令可以离线猜。生成器不拦短口令。要用自动的 16 位，或更长。
- U 盘如果是 FAT，粉碎未必能覆盖旧数据。剪走密钥文件之后，U 盘上还可能留着恢复得回来的副本。

所以卷口令不要写进 `VeraCrypt/config.sh`，不要和临时 PIN 相同，也不要在同事电脑上敲。同事那边只记 PIN。用完让脚本把自己和密钥文件粉碎，密钥文件不要再留第二份。
